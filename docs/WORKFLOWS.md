# Practical Workflows & Prompt Cookbook

Copy-paste recipes for getting maximum velocity out of `engg-skills-suite` across every stage of software delivery.

---

## Recipe 0: Choose the Delivery Mode (once per effort)

```text
/engg-plan Before planning, ask me the delivery-mode question (mvp-first or full-sequence) and confirm the baseline, then record both in .engg/delivery.yaml.
```

- **New idea or tight deadline:** `mvp-first` with `core_flow` set to the one journey that must work. Wave 1 is that flow plus the critical items; everything else is an increment.
- **Existing project, next feature:** keep the recorded mode; `baseline: existing` means the architecture and tools are fixed.
- **Starting over on purpose:** say so: `baseline: redo` is the only way the skills will redesign.

## Recipe 1: Grill & Harden an In-Progress Product Roadmap

**Goal:** Align `docs/ROADMAP.md` with actual repository reality, cut drag, pull high-risk items forward, and route every milestone to the right execution skill.

```text
/engg-roadmap Inspect docs/ROADMAP.md and cross-check it against our current codebase structure, tests, and open debt.
Walk me through your grill rounds (max 6 sharp questions per round) before rewriting anything.
Then produce the Roadmap Scorecard, Tightened Roadmap Delta, hardened docs/ROADMAP.md, and Suite Routing Matrix.
```

**Follow-up once approved:**

```text
Write the approved hardened roadmap to docs/ROADMAP.md, then run /engg-plan on Milestone 1 only to produce Wave 1 and Wave 2 atomic chunks.
```

## Recipe 2: Daily Chunk Shipping Loop (Build -> Audit -> Commit)

**Goal:** Ship one clean, verified, adversarially audited vertical increment without architectural drift.

```text
/engg-build Implement Chunk C1 from our plan.
Follow strict TDD: list the 5-category Test Matrix first, write the failing tests, implement the minimal clean production code upholding SOLID/DRY/KISS/ATOMIC, and run the full test/lint/typecheck/race suite.
```

**Mandatory immediately after green:**

```text
/engg-audit Run Mode A on all files created or modified in Chunk C1 (including the tests).
Fix every P0 and P1 finding with regression tests, re-run verification, and draft an atomic Conventional Commit message.
```

## Recipe 3: Greenfield Project from Scratch

1. **Frame the idea:**
   ```text
   /engg-ideate I want to build <brief idea>. Pressure-test it, compare 2-3 approaches, expose fatal risks, and lock a sharp V1 Project Charter.
   ```
2. **Design & Grill:**
   ```text
   /engg-architect Use the approved Project Charter and grill me across your focused rounds to produce a locked EDD and ADRs. Use /engg-research to verify live versions for any dependencies we pick.
   ```
3. **Plan & Execute:**
   ```text
   /engg-plan Break the locked EDD into MVP-first Waves and atomic chunks, then start /engg-build on Chunk 1.
   ```

## Recipe 4: Hardening an Existing Codebase (Brownfield Rescue)

```text
/engg-deep-audit Audit <directory or entire repo> against .engg/architecture.yaml, layer by layer.
(No contract yet? It will offer to draft the as-is contract and hand off to /engg-architect first.)
Produce the 7-pillar scorecard, severity-ranked P0-P3 findings, the strip list, the move list, and remediation waves.
```

Then convert the remediation plan into chunks:

```text
/engg-plan Turn the deep-audit REPORT.md into chunks per wave (Wave 1: safety-net tests + P0 fixes + ratchet; Wave 2: strip list; Wave 3: P1 hardening; Wave 4: moves toward the contract, inside-out; Wave 5: P2/P3 simplification).
```

Then execute each wave safely:

```text
/engg-refactor Execute Wave 1 from the plan: characterization tests on every hotspot first (prove they can fail), record the ratchet baseline, then the P0 fixes test-first. One commit per finding, with the gates green after each.
```

## Recipe 5: Tightening a Spec or Plan Generated by Another LLM

```text
/engg-audit Run Mode C on <path/to/spec.md>.
Flag hallucinated or stale tech claims, missing non-goals, unstated performance budgets, broken trust boundaries, happy-path-only assumptions, and over-engineering. Output a Tightened Spec Delta ([KEEP]/[REVISE]/[ADD]/[CUT]).
```

## Recipe 6: Adding a Feature Slice or Swapping an Adapter

- **New vertical feature slice:**
  ```text
  /engg-extend Use Mode A to add <feature name> matching our existing vertical slice conventions, strict TDD, and post-build /engg-audit.
  ```
- **New or swapped adapter (DB, cache, queue, payment, SDK, engine backend):**
  ```text
  /engg-extend Use Mode B to implement a <technology> adapter for <PortName>. Verify exact pinned package versions via /engg-research and run the shared LSP contract test suite against both our in-memory fake and the real adapter.
  ```

## Recipe 7: Evidence-Driven Debugging & Performance Tuning

```text
/engg-debug Investigate <symptom / latency spike / crash / frame drop / slow query>.
Do not patch yet—establish baseline numbers, create a minimal deterministic reproduction, gather profiler/EXPLAIN evidence, confirm root cause, then write a failing regression test before fixing.
```

## Recipe 8: Zero-Downtime Database Change

```text
/engg-data Design the schema change and expand-and-contract migration plan for <requirement>.
Verify lock safety, N-1 backward compatibility, batched backfill idempotency, and EXPLAIN (ANALYZE, BUFFERS) query plans.
```

## Recipe 9: Production Readiness & Safe Release

```text
/engg-ship Harden our CI pipeline, Dockerfile/IaC, observability/SLOs, and run the Production Readiness Gate checklist for <service/app> including a verified rollback runbook.
```
